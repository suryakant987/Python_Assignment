Utility Asset Registry

Backend for a state electricity distribution utility. It cleans daily handheld GPS survey exports, stores trusted asset records in PostgreSQL, and serves them over HTTP to authorised staff and the utility web map.

Python FastAPI PostgreSQL CLI + REST API Version 1.0.0

1. Overview

Field crews export a day’s work as a CSV. This application replaces manual re-typing into a spreadsheet with automated cleaning, permanent storage, access control, and queryable network APIs.

Part A — Ingestion tool Night-shift operators run one terminal command. Bad rows are rejected with reasons; good rows are stored.
Part B — Web service Staff and the web map call authenticated HTTP endpoints. Interactive docs live at /docs.

Capabilities

  • Load a day’s CSV with a single command
  • Standardise descriptions, coordinates, types, and surveyor names
  • Never drop a bad row silently — write it to a rejects file with a reason
  • Refuse duplicate asset_id values already in the database or the same file
  • Store assets and visit history in PostgreSQL
  • Search, filter, and page assets over the network
  • Role-based access: surveyor vs administrator
  • Cached summary reports for the web map
  • Request logging, rate limiting, and CORS for a configured map origin

4. Accounts & roles

RoleUsernamePasswordPermissions
Administrator admin Admin@123 Read, add, update, delete, bulk upload, create users
Surveyor surveyor Surveyor@123 Read, add, update only (delete refused)

Sign in via POST /auth/login. The response includes an access_token. Send it on later requests as: 

Authorization: Bearer <access_token>

The bootstrap admin is created (or password-synced) from BOOTSTRAP_ADMIN_USERNAME / BOOTSTRAP_ADMIN_PASSWORD in .env when the API starts.

5. Ingestion CLI

For operators who do not need to know Python:

python -m asset_registry.ingest data/survey_export.csv

Options

python -m asset_registry.ingest --help
python -m asset_registry.ingest data/survey_export.csv ^
  --rejects outputs/rejects.csv ^
  --map outputs/assets.geojson ^
  --report outputs/summary.txt
python -m asset_registry.ingest data/survey_export.csv --strict
OptionMeaning
csv_pathPath to the handheld export (required)
--rejectsRejects file path (default outputs/rejects.csv)
--mapGeoJSON map file (default outputs/assets.geojson)
--reportPlain-text summary (default outputs/summary.txt)
--strictAbort the whole run on the first rejected row

Behaviour

  • Confirms every expected column is present before processing
  • Accepts valid new assets into PostgreSQL
  • Rejects invalid rows and continues (unless --strict)
  • Rejects an asset_id that already exists in the database or appears twice in the file
  • Prints rows read / accepted / rejected and the rejects file path
  • Appends one dated line to logs/ingest.log
Re-running the same CSV against a database that already holds those assets accepts 0 rows and rejects duplicates with asset_id: is already in use.

6. Cleaning & validation

Automatic cleaning

  • Descriptions: trim, collapse spaces, consistent capitalisation
  • Coordinates with compass letters (e.g. 28.6148 N) → signed decimals
  • Asset types matched regardless of letter case
  • Surveyor names standardised so variants of one person count once
  • attribute_json parsed into ordinary JSON data

Validation rules (CSV and API)

FieldRuleOn failure
asset_idPresent, XX-1234, not already in useReject
name3–120 characters after tidyingReject
asset_typepole, valve, manhole, transformerReject
latitudeNumber between −90 and 90Reject
longitudeNumber between −180 and 180Reject
elevation_mNumber if present; blank → not recordedStore null / reject if non-numeric
surveyed_onValid date, not in the futureReject
statusactive, decommissioned, proposedReject
condition_scoreWhole number 0–10Reject
attribute_jsonValid JSON objectReject
Cross-fieldDecommissioned assets may not have condition > 2Reject

8. Reports

PathPurpose
GET/reports/summaryCounts, averages, worst asset per type, survey extent, totals (cached up to 60s)
GET/reports/repairsIn-service assets with condition < 5
GET/reports/most-visitedAssets visited most often
GET/reports/nearestNearest asset to a lat/lon (great-circle km)
GET/reports/surveyorsDistinct surveyors on a given day (?on=YYYY-MM-DD)
GET/statusPublic liveness check for monitoring

The summary cache is discarded immediately when any asset is added, corrected, or removed, so a stale summary is never served after a change.

9. Security & non-functional behaviour

  • Passwords stored with bcrypt (not recoverable)
  • JWT credentials expire after JWT_EXPIRE_MINUTES
  • Secrets come from the environment — never hard-coded
  • CORS limited to origins listed in CORS_ORIGINS
  • Rate limit: 60 requests per minute per caller (/status exempt)
  • Every request is logged with path, status, and duration
  • JSON responses include duration_ms where applicable

10. Database

TablePurpose
usersAccounts, hashed passwords, roles
assetsCurrent asset master data; unique asset_id
visitsVisit history (date, surveyor, condition, notes)

Deleting an asset cascades to its visits so no orphaned history remains. Switching from local PostgreSQL to an enterprise server is a change of DATABASE_URL only. Tables are created automatically when the API or ingest tool starts (init_db).

12. Testing

pytest

Tests use a throwaway database named asset_registry_test and never touch live asset_registry data. Coverage includes cleaning boundaries, rejection of bad rows, duplicate re-ingest refusal, network CRUD, missing records, successful sign-in, and surveyor delete refusal.
